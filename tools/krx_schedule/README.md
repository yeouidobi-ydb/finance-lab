# krx_schedule

특정 날짜가 KRX 휴장일인지 조회하고, 그 날짜가 들어간 공지를 함께 보여 준다.
휴장일 목록은 **연도별로 한 번 받아 저장**해 두고, 이후 조회는 저장본으로 한다.
Python과 Rust 버전이 같은 결과를 출력하고, 같은 저장 파일을 같이 쓴다.

## 실행

```bash
# Python (표준 라이브러리만 사용)
python krx_schedule.py 2026-12-25

# Rust
cargo run --release -- 2026-12-25
```

날짜를 생략하면 오늘(KST)을 조회한다. 다른 Python 스크립트에서는 `from krx_schedule import is_trading_day`로 쓸 수 있다(같은 저장본을 쓴다).

## 휴장일 저장과 갱신

```bash
python krx_schedule.py --update        # 올해(KST) 휴장일을 받아 저장본 교체
python krx_schedule.py --update 2027   # 특정 연도
cargo run --release -- --update 2027   # Rust도 같다
```

- 저장 위치: `tools/krx_schedule/data/krx_holidays_<연도>.json` (`data/`는 `.gitignore`에 있어 커밋되지 않음)
  - 환경 변수 `KRX_SCHEDULE_DATA_DIR`로 위치를 바꿀 수 있다.
  - Rust는 기본 위치가 빌드할 때 소스 폴더로 고정된다. 빌드한 실행 파일을 다른 곳으로 옮겨 쓰면 이 환경 변수를 지정한다.
- 저장본에는 받은 시각(`fetched_at`, KST)이 들어 있고, 조회 결과에 `- 휴장일 데이터: <날짜> 받음 (<출처>)`으로 표시된다.

### 언제 다시 받나 (예약 작업 없이, 조회할 때 판단)

| 상황 | 동작 | 표시 |
|---|---|---|
| 그 해 저장본 없음 | 받아서 저장 | `방금 새로 받아 저장` |
| 올해 이후 연도, 마지막 **월·목 0시(KST)** 뒤에 받은 저장본 | 저장본 사용 (네트워크 호출 없음) | `저장본 사용` |
| 올해 이후 연도, 마지막 월·목 0시 전에 받은 저장본 | 다시 받아 저장 | `저장본이 오래돼 다시 받아 저장` |
| 지난 연도, 그 해가 끝나기 전에 받은 저장본 | 한 번 더 받아 저장 (그 뒤로는 안 바뀜) | `저장본이 오래돼 다시 받아 저장` |
| 올해보다 뒤 연도인데 저장본 없음 | 받아 쓰기만 하고 저장 안 함 | `다음 해 이후라 저장 안 함 · 확정 전일 수 있음` |

- **월·목 갱신:** 선거일·임시공휴일(예: 2026-06-03)처럼 해 중간에 정해지는 휴장일을 반영하려는 규칙이다. KRX 반영 후 **늦어도 3~4일 안에** 저장본에 들어온다. 급하면 `--update`를 바로 돌린다.
- **미래 연도:** KRX는 먼 미래 연도에도 달력을 주지만 확정 전이라 빠진 날이 있다(예: 2030년 목록에 연말휴장일이 없음). 그래서 자동 저장하지 않는다. `--update <연도>`로 직접 저장한 것은 월·목마다 갱신된다.
- **다시 받기 실패:** 저장본이 오래됐는데 KRX 조회가 실패하면 오래된 목록으로 넘기지 않고 오류(종료 코드 1)로 멈춘다. 기존 저장본은 그대로 둔다. 따라서 월·목이 지난 뒤 처음 조회할 때는 KRX에 접속할 수 있어야 한다(`is_trading_day()`도 같다).
- 저장본이 깨졌거나 비었거나 연도·받은 시각 형식이 안 맞으면 "휴장일 없음"으로 넘기지 않고 오류(종료 코드 1)로 멈춘다. `--update`로 다시 받으면 된다.
- KRX 응답이 비었거나 날짜가 비었거나 다른 해 날짜가 섞여 있으면 오류로 멈추고 기존 저장본을 덮어쓰지 않는다.

## 테스트

네트워크 호출 없이 돈다. Python과 Rust가 같은 경우들(응답 해석, 월·목 갱신 규칙, 저장본 검증, 저장·갱신 흐름)을 확인한다.

```bash
python -m unittest -v test_krx_schedule   # Python
cargo test                                # Rust
```

CI는 위 두 테스트에 더해, Python이 쓴 저장본을 Rust가 읽고 Rust가 쓴 저장본을 Python이 읽는지도 확인한다(`.github/workflows/ci.yml`).
Rust를 로컬에서 돌리려면 [rustup](https://rustup.rs)을 설치한다. Windows는 Visual Studio Build Tools(C++ 빌드 도구)도 필요하다.

## 출력 판정

- `휴장 (주말)` / `휴장 (<휴장일 이름>)` / `개장`
- KRX 조회가 실패하거나 휴장일 목록이 비어 있으면 "휴장일 없음"으로 넘기지 않고 오류(종료 코드 1)로 멈춘다.
